## 一、核心概念：区块链、Web3 与智能合约

### 1. 区块链的起点：比特币白皮书

区块链技术最早大规模落地于比特币。2008 年，美国次贷危机背景下，中本聪发布了比特币白皮书：《Bitcoin: A Peer-to-Peer Electronic Cash System》。白皮书中并没有直接使用"blockchain"这个词，但比特币协议采用了类似结构：将一段时间内的交易数据打包，存入一个叫"区块"的数据结构，随着时间推移产生越来越多区块，区块按时间顺序连接起来，最终形成"区块链"。

比特币诞生的核心目标，是解决传统金融系统中可能存在的：资金管理不透明、货币超发、中心化机构不合规操作、用户无法验证资金实际去向。比特币通过公共账本记录每一笔交易，并通过奖励机制激励节点参与维护账本。

> *比特币并不是为了"更快支付"而设计的，它更核心的价值是用透明账本和共识机制降低对中心化机构的依赖。*

### 2. 比特币与以太坊的关键区别：智能合约

比特币最初主要用于转账和简单脚本，不支持复杂业务逻辑（`if` 判断、`for` 循环、复杂状态管理等），通常不被认为是图灵完备的。

2013 年，Vitalik Buterin 提出以太坊。以太坊在区块链数据结构基础上加入了智能合约，使开发者可以在链上编写和执行复杂逻辑。

| 对比项 | 比特币 | 以太坊 |
|--------|--------|--------|
| 核心定位 | 点对点电子现金、价值存储 | 通用智能合约平台 |
| 主要功能 | 转账、简单脚本 | 任意业务逻辑、DApp |
| 图灵完备 | 否 | 是 |
| 开发重点 | 资产转移 | 链上程序与状态管理 |

> *可以把比特币理解为"链上账本 + 价值存储"，把以太坊理解为"链上账本 + 可编程业务系统"。后续 ERC20、NFT、DAO、跨链，本质上都依赖这个可编程能力。*

### 3. 区块链的两个底层哲学：去中心化与共识

#### 去中心化：没有单一中心服务器

去中心化系统的核心含义是：网络中没有单一中心服务器；任意参与方可以在没有中介的情况下交互；数据由多个节点共同维护；单个节点无法随意篡改整体账本。例如，张三给李四转账，不再依赖银行、支付宝这类中心化机构记录交易，而是由区块链网络共同记录。

#### 共识：让所有节点认可同一份账本

去中心化网络没有中心化记账方，因此必须解决：谁来判断数据是真是假？共识机制负责让网络中的节点对数据达成一致。一笔交易上链前，节点需要验证：交易是否有发送方签名、发送方余额是否足够、交易格式是否合法、是否存在双花等异常情况。当多数节点验证通过并更新账本后，交易才算真正"上链"。

> *去中心化解决的是"谁来维护系统"的问题；共识解决的是"大家如何相信同一份结果"的问题。二者缺一不可。*

### 4. 女巫攻击与共识机制

如果任何节点都能无限提交数据，就可能出现大量虚假交易冲击网络（Sybil Attack）。为防止攻击者用低成本伪造大量身份，区块链需要提高作恶成本。

#### PoW：工作量证明

节点想记账，必须先完成大量计算。计算难题很难解，但验证答案是否正确很容易。想伪造大量交易，就必须付出大量算力和电力成本。PoW 的问题是能源消耗高。

#### PoS：权益证明

以太坊在 2022 年完成重要升级，从 PoW 转向 PoS。节点不再靠大量计算获得记账权，而是需要预先质押资产。如果提交错误或恶意信息，质押资产会被罚没。

| 对比项 | PoW | PoS |
|--------|-----|-----|
| 安全基础 | 算力、电力成本 | 质押资产成本 |
| 典型代表 | 比特币 | 以太坊现阶段 |
| 主要问题 | 能耗高 | 依赖质押和惩罚机制 |
| 作恶代价 | 算力投入被浪费 | 质押资产被罚没 |

### 5. 区块链的效率与安全取舍

区块链系统的特点是：去中心化程度高、数据安全性强、篡改成本高，但效率低、成本高。更适合放在链上的数据通常具有以下特征：有明确所有权、不应被单方篡改、需要长期存在、多方需要共同验证、涉及资产、权益、身份、凭证或规则执行。

> *开发 DApp 前必须先问一句：这个应用真的需要去中心化吗？如果只是普通 CRUD 应用，强行上链反而会增加成本和复杂度。*

### 6. Web3：可拥有资产的互联网

| 阶段 | 典型能力 |
|------|---------|
| Web1 | 读 |
| Web2 | 读 + 写 |
| Web3 | 读 + 写 + 拥有 |

Web3 应用的核心特征是：应用中可以存储资产；资产所有权归用户；除用户外，其他人不能随意更改；资产可以跨应用使用、交易或组合。

**链上游戏资产示例**：传统游戏中，用户获得的装备、道具、皮肤等资产通常存储在游戏公司服务器里，如果游戏停服，资产可能消失。Web3 模式下，游戏资产可以作为链上资产存在，用户真正拥有这些资产，游戏停服后资产仍然存在，其他开发者可以基于这些资产开发新应用。

**金融透明度示例**：传统金融中，用户把钱存入银行后只能相信对方按承诺使用资金。区块链和智能合约可以让资金流向、资产储备、规则执行更加透明。

> *Web3 的核心不只是"虚拟币交易"，而是让互联网具备资产层。资产一旦可编程、可组合，就会产生新的应用形态。*

### 7. 智能合约的特点

| 特点 | 说明 |
|------|------|
| 去中心化 | 部署在区块链上，由网络节点共同维护，不依赖单个机构控制 |
| 数据透明 | 区块链是公共账本，合约数据和交易记录对网络参与者可见 |
| 不可篡改 | 合约部署后通常不能随意修改或删除 |
| 原子性 | 多方操作在同一笔交易中整体执行：要么全部成功，要么全部失败 |

### 8. 基于智能合约的常见应用

| 应用 | 全称 | 说明 |
|------|------|------|
| DeFi | Decentralized Finance | 去中心化金融，让用户不依赖中介参与金融活动 |
| NFT | Non-Fungible Token | 非同质化通证，可代表艺术品、身份、凭证、真实资产映射等 |
| DAO | Decentralized Autonomous Organization | 去中心化自治组织，用链上规则和投票管理组织 |
| 链游 | GameFi / On-chain Game | 将游戏资产、规则、交易放到链上 |
| 跨链应用 | Cross-chain Application | 在不同区块链之间传递消息、资产或状态 |

## 二、核心步骤：创建钱包账户并发送第一笔交易

### Step 1：理解托管账户与自托管账户

| 类型 | 控制权 | 典型代表 | 优点 | 风险 |
|------|--------|---------|------|------|
| 托管账户 | 第三方掌握私钥和资产控制权 | 中心化交易所 | 使用方便，类似银行账户 | 用户不真正掌握资产 |
| 自托管账户 | 用户自己掌握私钥 | MetaMask 等钱包 | 用户完全控制资产 | 私钥丢失无法找回 |

> *Web3 里常说 "Not your keys, not your coins"。不是你掌握私钥，就不算真正掌握资产。*

### Step 2：安装 MetaMask

进入 `https://metamask.io`，下载对应浏览器插件（课程以 Chrome 为例）。MetaMask 是浏览器插件钱包，主要功能包括：创建自托管钱包、管理账户地址、保存本地加密后的钱包数据、签名交易、与 DApp 连接、显示 Token、NFT 和交易记录、切换不同区块链网络。

### Step 3：创建新钱包

选择"Create a new wallet"，设置本地密码。**注意**：MetaMask 设置的密码不是私钥，也不是助记词。它的作用是加密本机中的钱包数据、防止别人直接打开你电脑上的 MetaMask。它不会上传到 MetaMask 的中心化数据库，也不能由 MetaMask 官方帮你恢复。

> *很多新手会误以为 MetaMask 密码就是账户密码。实际上，真正控制资产的是助记词和私钥；MetaMask 密码只是本地软件锁。*

### Step 4：保存助记词

创建钱包时，MetaMask 会生成一组助记词（通常是 12 个英文单词）。助记词是钱包的最高权限凭证，可以：恢复整个钱包、派生多个私钥、控制该助记词下生成的多个账户、在新设备上重新导入钱包。

推荐保存方式：写在纸上，放在安全、隐私、自己能找到的位置。**不截图、不上传网盘、不发给任何人、不输入到陌生网站。**

> *助记词是 Web3 里的最高权限。任何向你索要助记词的人，基本都可以直接视为诈骗。*

### Step 5：理解助记词、私钥、公钥、地址的关系

```
助记词 Mnemonic
  → 种子 Seed
    → 主密钥 Master Key
      → 私钥 1 → 公钥 1 → 地址 1
      → 私钥 2 → 公钥 2 → 地址 2
      → 私钥 N → 公钥 N → 地址 N
```

| 概念 | 作用 | 泄露后果 |
|------|------|---------|
| 助记词 | 恢复整个钱包，可派生多个私钥 | 该助记词下所有账户都可能被控制 |
| 私钥 | 控制某一个账户 | 该私钥对应账户资产可能被转走 |
| 公钥 | 用于验证签名等 | 通常可公开 |
| 地址 | 链上账户标识 | 可公开，用于收款和查询 |

### Step 6：认识 MetaMask 钱包界面

**网络选择**：左上角可切换网络（Ethereum Mainnet、Linea Mainnet、Sepolia 测试网等）。不同网络之间默认不互通，同一地址在不同网络上资产状态互不相同。

**账户列表**：基于同一组助记词可以创建多个账户。每个账户都有账户名、地址、私钥、余额、二维码。

**Token、NFT 与活动记录**：

| 区域 | 说明 |
|------|------|
| Tokens | 显示 ERC20 等同质化通证 |
| NFTs | 显示 NFT 资产 |
| Activity | 显示交易、转账、合约交互记录 |

| 类型 | 特点 | 类比 |
|------|------|------|
| 同质化通证 FT / ERC20 | 每一单位彼此等价 | 1 元钱和另 1 元钱 |
| 非同质化通证 NFT | 每一个都独一无二 | 一幅画和另一幅画 |

### Step 7：领取 Sepolia 测试币

打开 Chainlink Faucet（`https://faucets.chain.link`），选择 Sepolia 网络，领取 Sepolia ETH 和 LINK。流程：打开 Faucet → 选择 Sepolia → 勾选测试资产 → 复制 MetaMask 地址 → 粘贴 → 完成人机验证 → 领取 → 在 Sepolia Etherscan 查看交易哈希。

**交易哈希 Transaction Hash** 是一笔交易的唯一 ID，通过它可以在区块浏览器中查询：交易状态、From 地址、To 地址、转账金额、Gas 费用、区块高度、时间、合约交互详情。

### Step 8：导入 LINK Token

ETH 是以太坊网络的原生通证，通常会自动显示。但 LINK 这类 ERC20 通证需要在 MetaMask 中导入 Token 合约地址：在 Sepolia Etherscan 中找到 LINK Token 合约地址 → MetaMask → Import Tokens → 粘贴地址 → 确认导入。

> *原生通证和 ERC20 通证的显示逻辑不同。ETH 是链底层资产；ERC20 的余额本质上是某个合约里记录的一组账本数据。*

### Step 9：发送第一笔链上交易

操作流程：切换到 Sepolia 测试网 → 确保账户 1 有测试 ETH → 点击 Send → 粘贴账户 2 地址 → 输入转账金额 → Next → 查看预估 Gas Fee → Confirm → 等待 Pending → Confirmed → 区块浏览器查看详情。

| 状态 | 含义 |
|------|------|
| Pending | 交易已发出，但尚未被确认 |
| Confirmed | 交易已被打包并写入区块 |
| Failed | 交易失败，可能是 Gas 不足、合约执行失败等 |

## 三、Gas、Gas Limit、Gas Price 与 EIP-1559

### 1. 为什么需要 Gas？

区块链网络中，节点需要为每笔交易执行计算、存储数据、同步状态。为了激励节点参与维护网络，用户必须为交易支付手续费。

| 网络 | 原生通证 |
|------|---------|
| Ethereum | ETH |
| Polygon | MATIC |
| Avalanche | AVAX |
| Sepolia 测试网 | Sepolia ETH |

### 2. Gas Fee 的组成

```
Gas Fee = Gas Limit × Gas Price
```

**Gas Limit**：交易最多允许消耗多少计算单元。普通 ETH 转账约 21,000 Gas；部署合约通常较高。

**Gas Price**：用户愿意为每个计算单元支付多少费用。网络拥堵时上升，空闲时下降。

> *Gas Limit 像"要做多少活"，Gas Price 像"每单位活给多少钱"。最终手续费是二者相乘。*

### 3. EIP-1559：以太坊手续费机制升级

| 字段 | 含义 |
|------|------|
| Base Fee | 基础费用，会被销毁（退出 ETH 流通） |
| Max Fee | 用户愿意支付的最高总费用 |
| Max Priority Fee | 给验证者的小费，用于提高交易优先级 |

Base Fee 不支付给验证者，而是被销毁，会影响 ETH 的供应量。当链上活动频繁、销毁量较大时，ETH 可能出现阶段性通缩。

> *EIP-1559 对普通开发者的日常编码影响不大，但理解它有助于看懂区块浏览器里的交易费用字段。*

## 四、密码学基础

### 1. 密码学解决什么问题？

密码学的基本目标是：将明文转换为密文，让未经授权的人无法理解密文，让授权方可以把密文还原为明文，证明消息来源，保证数据未被篡改。

### 2. 哈希函数

哈希函数将任意长度的数据转换为固定长度的哈希值。

| 特点 | 说明 |
|------|------|
| 确定性 | 同样输入永远得到同样输出 |
| 高效性 | 计算哈希值很快 |
| 单向性 | 很难从哈希值反推出原文 |
| 雪崩效应 | 输入微小变化会导致输出完全不同 |
| 数据指纹 | 哈希值可作为文件或数据的唯一指纹 |

**示例：文件校验**：软件下载网站常提供 checksum。用户下载文件后，可以自己计算文件哈希值，并与官网提供的 checksum 对比。如果一致，说明文件大概率未被篡改。

> *哈希不是"加密"。加密通常可以解密还原；哈希强调的是单向指纹，正常情况下无法还原原文。*

### 3. 对称加密与非对称加密

**对称加密**只有一个密钥，加密和解密都用同一个密钥。问题是：密钥怎么安全地交给对方？

**非对称加密**有一对密钥：公钥（可公开，用于加密、验证签名）和私钥（必须保密，用于解密、签名、控制账户）。区块链主要使用非对称加密体系。

### 4. 非对称加密的应用：加密通信

Alice 公开自己的公钥 → Bob 获取 Alice 公钥 → Bob 用 Alice 公钥加密消息 → 密文公开传输 → Alice 用自己的私钥解密。因为只有 Alice 拥有对应私钥，即使密文被别人看到，也无法解密。

### 5. 非对称加密的应用：数字签名

签名流程：Bob 准备消息 → 对消息做哈希 → 用自己的私钥加密哈希值 → 生成数字签名 → 发布消息 + 数字签名。

验证流程：Alice 获取消息和签名 → 用 Bob 公钥解密签名得到哈希值 1 → 对消息再做一次哈希得到哈希值 2 → 对比两个哈希值是否一致。

在区块链交易中：钱包使用私钥对交易签名，网络节点用公钥验证签名。验证通过后，说明交易确实由该账户控制者发起。所以私钥一旦泄露，别人就能伪造你的签名，转走资产。

> *链上世界里，"签名"基本等同于"本人授权"。所以不要随便在陌生网站点击签名，尤其是看不懂内容的签名请求。*

### 6. 助记词生成私钥的简化过程

大致流程：生成随机数 → 校验和处理 → 切分二进制数据 → 映射到词库单词 → 得到 12/24 个助记词 → 助记词通过算法生成种子 → 种子生成主密钥 → 主密钥派生多个子私钥 → 每个私钥生成公钥与地址。

| 名称 | 作用 |
|------|------|
| BIP-39 | 助记词标准 |
| PBKDF2 | 从助记词派生种子 |
| HD Wallet | 分层确定性钱包 |
| BIP-32 / BIP-44 | 常见分层派生相关标准 |

> *作为入门开发者，不需要一开始就手写助记词派生算法。更重要的是知道权限链路：助记词 > 私钥 > 地址。*

## 六、本课核心结论

1. 区块链的早期实践来自比特币，它通过公共账本、去中心化网络和共识机制解决中心化金融系统中的信任问题。
2. 以太坊在区块链基础上加入智能合约，使区块链从"转账系统"扩展为"可编程应用平台"。
3. 去中心化和共识是区块链最核心的两个概念，但它们会带来效率下降和成本上升。
4. Web3 的关键是让互联网不仅能读写数据，还能让用户拥有和转移数字资产。
5. 自托管钱包让用户真正掌握资产，但助记词和私钥一旦丢失或泄露，资产无法恢复。
6. MetaMask 是 Web3 入门最常用的钱包工具之一，可用于创建账户、签名交易、连接 DApp、管理 Token 和 NFT。
7. 哈希函数、非对称加密和数字签名是区块链交易可信执行的密码学基础。
8. Gas Fee 是链上操作的手续费，由计算量和网络拥堵程度共同影响。
9. EIP-1559 将以太坊手续费拆分为基础费用和优先费用，其中基础费用会被销毁。
10. Remix 是学习 Solidity 和编写第一个智能合约的低门槛工具，适合入门和快速验证。
