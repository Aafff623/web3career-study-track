# Case: 并行预习笔记调度

> 2026-05-19 · Web3 基础 6 节并行整理

## 场景

用户提供了 6 个 Web3 基础模块的 Handbook 原文，要求并行整理为预习笔记（原文+批注），同时维护级联文件。

## 初始方案（有缺陷）

**调度方式**：派 2 个 Agent，每个处理 2 个模块，各自负责笔记 + 级联更新。

**暴露问题**：

| # | 问题 | 表现 | 根因 |
|---|------|------|------|
| 1 | 索引不一致 | Agent 1 没更新 `__index__.md`，Agent 2 更新了 | 两个 Agent 操作共享索引文件，行为不可控 |
| 2 | 状态符号混乱 | Agent 2 用 🟢，主调度用 ✅ | prompt 未统一规范 |
| 3 | 通知缺失 | Agent 完成后无主动通知 | 缺少消息回传机制 |
| 4 | 级联维护分散 | Agent 各自改了一部分级联文件 | 职责边界不清 |

## 优化方案

**核心原则：Agent 只写内容，主调度统一级联。**

```
┌─────────────────────────────────────────────┐
│                主调度（Claude）               │
│  · 派发 Agent（只含笔记+实践文件的任务）      │
│  · 统一 __index__.md 状态更新                │
│  · 统一 daily-log 产出表                     │
│  · 统一 memory 进度数字                      │
│  · 统一 README 进度表                        │
│  · 消息通知用户                              │
└──────────┬──────────────┬───────────────────┘
           │              │
    ┌──────▼──────┐ ┌─────▼──────┐
    │   Agent 1   │ │   Agent 2   │
    │ 写笔记 A+B  │ │ 写笔记 C+D  │
    │ 写实践文件   │ │ 写实践文件   │
    │ 不动索引     │ │ 不动索引     │
    │ 不动日志     │ │ 不动日志     │
    └─────────────┘ └─────────────┘
```

**Agent Prompt 模板要点**：
1. 明确只写 README.md + practice-*.md
2. 明确"不要更新 `__index__.md`、daily-log、memory、README"
3. 统一状态符号（✅ 表示已完成含批注）
4. 统一批注格式（`> *批注内容*`）
5. 统一实践文件结构（目标 → 流程 → 验收标准）

**主调度 Checklist**：
1. [ ] 等 Agent 完成
2. [ ] 验证文件产出（glob 检查）
3. [ ] 抽查笔记质量（读前 50 行）
4. [ ] 统一更新 `pre_study/__index__.md`
5. [ ] 统一更新 `daily-log/.../YYYY-MM-DD.md` 产出表
6. [ ] 统一更新 `daily-log/.../__index__.md` 关联引用
7. [ ] 更新 `memory/project_prestudy_status.md`
8. [ ] 更新 `README.md` 进度表
9. [ ] 通知用户结果

## 关键教训

1. **共享文件由主调度统一操作** — Agent 并发写同一个文件会冲突或不一致
2. **Prompt 要显式禁止 Agent 操作某些文件** — 不是说"你应该做什么"就够了，还要说"不要做什么"
3. **状态符号在 prompt 里统一** — 不能假设 Agent 会沿用之前的符号体系
4. **完成通知是 workflow 的一部分** — 不是可选的

## 适用场景

- 需要并行处理多个同构任务（如多个模块笔记、多个文件重构）
- 任务产出需要汇聚到共享索引或状态文件
- 主调度需要对一致性负责
