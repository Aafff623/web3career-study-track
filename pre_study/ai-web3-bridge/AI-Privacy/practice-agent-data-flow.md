# Practice: Agent 数据流图与隐私边界设计

> 模块：AI × Web3 交叉 · AI-Privacy

## 目标

为一个 DeFi Agent 设计完整的数据流图和隐私边界方案，覆盖数据分类 → 流动规则 → 用户控制。

## 场景

用户使用 AI Agent 管理 DeFi 投资组合。Agent 需要：读取钱包余额和交易历史、分析持仓风险、生成调仓建议、执行链上交易。

## 流程

### 1. 数据清单

| 数据项 | 来源 | 敏感度 | 存储位置 |
|--------|------|--------|---------|
| 钱包地址 | 用户输入 | 中 | 应用后端 |
| 助记词/私钥 | 用户输入 | 极高 | 不应存在任何地方 |
| 余额/持仓 | 链上 RPC | 中 | 不存储，实时查询 |
| 交易历史 | 链上 RPC | 中 | 不存储，按需查询 |
| API key | 环境变量 | 高 | 后端安全存储 |
| 用户偏好 | 用户输入 | 低 | 本地/加密存储 |
| 聊天记录 | Agent 交互 | 中 | 加密存储，可删除 |
| 模型上下文 | 推理时拼装 | 中 | 不持久化 |

### 2. 数据流图

```
用户设备                    应用后端                    第三方
┌──────────┐            ┌──────────────┐            ┌──────────┐
│ 用户输入  │───脱敏──→│ 后端处理      │───摘要──→│ 云端模型  │
│ 钱包签名  │←──指令────│ Policy Engine │←──响应────│ 推理服务  │
│ 本地偏好  │           │ Secret Mgmt   │           │          │
└──────────┘            │ Audit Log     │           └──────────┘
      │                 └──────┬───────┘
      │ 链上查询               │
      ↓                        ↓
┌──────────┐            ┌──────────────┐
│ 链上数据  │←──RPC────│ Indexer/Explorer│
│ (公开)    │───只读──→│ (公开)        │
└──────────┘            └──────────────┘
```

### 3. 流动规则

| 数据流向 | 规则 | 示例 |
|----------|------|------|
| 用户 → 模型 | 只传摘要，不传原文 | "最近 3 笔大额交易"而非全部历史 |
| 链上 → 模型 | 只传必要字段 | 余额 + 持好列表，不传全部交易 |
| 模型 → 第三方 | 最小化 + 脱敏 | 风险评分请求不含用户地址 |
| 后端 → 日志 | hash + 摘要 | 原文加密存储，日志只记 hash |
| 本地 → 后端 | 加密传输 | 用户偏好加密后上传 |

### 4. 用户控制开关

| 控制项 | 默认 | 用户可操作 |
|--------|------|-----------|
| 读取钱包余额 | 开 | 关闭后 Agent 无法获取余额 |
| 分析交易历史 | 关 | 开启并设定时间范围 |
| 保存聊天记忆 | 关 | 开启后可随时删除 |
| 发送数据给云端模型 | 关 | 开启后可随时撤销 |
| 保存风险偏好 | 开 | 可查看、修改、删除 |

### 5. Secret Management 策略

```yaml
secrets:
  private_key:
    storage: "never_in_system"  # 助记词/私钥不应存在
    action: "reject_and_alert"
  
  api_key:
    storage: "env_variable"  # 后端环境变量
    rotation: "90_days"
    scope: "per_service"  # 不同服务不同 key
  
  session_token:
    storage: "memory_only"  # 不持久化
    ttl: "1_hour"
    scope: "single_task"
```

## 验收标准

- [ ] 数据清单完整（包含所有敏感数据项）
- [ ] 数据流图清晰（用户/后端/第三方/链上）
- [ ] 流动规则明确（哪些脱敏、哪些摘要、哪些不传输）
- [ ] 用户控制开关具体到动作和数据类型
- [ ] Secret Management 策略覆盖 key 生命周期
