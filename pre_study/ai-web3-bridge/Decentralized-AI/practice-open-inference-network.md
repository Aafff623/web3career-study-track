# Practice: 开放推理网络最小规格设计

> 模块：AI × Web3 交叉 · Decentralized-AI

## 目标

设计一个开放推理网络的最小规格，覆盖角色 → 请求 → 报价 → 验证 → 结算 → 争议全流程。

## 场景

DAO 治理需要 AI 自动总结提案、生成投票建议摘要、分析预算合理性。这些任务需要多个推理节点协作完成。

## 流程

### 1. 支持任务类型

| 任务 | 输入 | 输出 | 风险等级 | 隐私要求 |
|------|------|------|---------|---------|
| 提案摘要 | 提案文本 + 论坛链接 | 结构化摘要 | 低 | 低 |
| 预算分析 | 预算表 + 历史拨款 | 分析报告 | 中 | 中 |
| 投票建议 | 提案 + 社区立场 | 多视角分析 | 高 | 低 |
| 链上数据解读 | 交易 hash + 合约地址 | 解读报告 | 中 | 中 |

### 2. 网络角色

| 角色 | 职责 | 激励 |
|------|------|------|
| 请求方 | 发送任务请求，支付费用 | 获得推理结果 |
| 推理节点 | 执行推理任务，返回结果 | 获得报酬 |
| 评测者 | 验证结果质量，抽样检查 | 获得评测奖励 |
| 支付方 | 管理资金池，执行结算 | 收取手续费 |
| 仲裁者 | 处理争议，做出裁决 | 获得仲裁奖励 |


### 5. 验收与结算状态机

```
请求发出 → 节点报价 → 接受报价 → 执行推理 → 提交结果
    ↓           ↓           ↓           ↓           ↓
  超时取消   无响应取消   超时取消    失败重试   评测验证
                                              ↓
                                    ┌─────────┴─────────┐
                                    ↓                   ↓
                              质量合格              质量不合格
                                    ↓                   ↓
                              结算付款              争议仲裁
                                    ↓                   ↓
                              任务完成            退款/重试
```

### 6. 结算规则

| 状态 | 规则 |
|------|------|
| 成功 | 节点获得报酬，评测者获得验证奖励 |
| 失败 | 节点无报酬，请求方可重试或退款 |
| 超时 | 节点无报酬，请求方全额退款 |
| 争议 | 仲裁者裁决，根据证据分配资金 |
| 质量不合格 | 降低节点声誉，部分或全部退款 |

### 7. 上链信息

| 信息 | 存储方式 | 说明 |
|------|---------|------|
| 任务 hash | 链上 | 任务唯一标识 |
| 输出 hash | 链上 | 结果完整性证明 |
| 结算记录 | 链上 | 付款/退款/争议 |
| 节点声誉 | 链上 | 历史质量评分 |
| 评测证据 | 哈希上链 | 原文链下存储 |

## 验收标准

- [ ] 支持至少 4 种任务类型
- [ ] 5 个角色职责和激励明确
- [ ] 请求格式包含必要字段
- [ ] 结算状态机完整（成功/失败/超时/争议）
- [ ] 上链信息明确（哪些上链，哪些哈希上链）
