# Practice: Agent 受限支付钱包最小练习

> 模块：AI × Web3 交叉 · Agent-Wallet

## 目标

设计一个"Agent 受限支付钱包"的最小方案，把"有限授权、自动执行、随时撤销、可追踪"四件事串起来。

## 场景

用户允许 Agent 在一天内最多花 5 USDC，用来支付某个白名单 API 或工具服务。Agent 可以自动完成小额支付，但不能转账给任意地址，也不能修改授权。

## 流程

1. 定义用户授权参数：
   - 额度：≤ 5 USDC / 天
   - 目标地址：白名单（仅指定 API 服务合约）
   - 时间窗口：24 小时 session key
   - 允许方法：仅 transfer / approve（指定 token + spender）

2. 定义 Agent 自动执行边界：
   - 额度内 → 自动执行，记录日志
   - 超额度 → policy 拒绝
   - 非白名单地址 → guard 拦截
   - 方法不在白名单 → guard 拦截

3. 定义 human-in-the-loop 节点：
   - 超额度支付 → 必须用户确认
   - 任何 approve（授权）操作 → 必须用户确认
   - session key 创建 / 撤销 → 必须用户确认

4. 定义 simulation 展示内容：
   - 你将支付多少 USDC
   - 接收方是谁
   - 交易是否会改变其他授权
   - 失败时的损失

5. 定义撤销机制：
   - 用户手动关闭入口
   - session key 到期自动失效
   - 连续 3 次支付失败自动暂停

6. 定义审计日志字段：
   - 时间、工具名、输入参数、输出结果、policy 判断、tx hash、用户确认（如适用）

## 验收标准

- [ ] 授权参数完整（额度 / 目标 / 时间 / 方法）
- [ ] 自动执行 + policy 拒绝 + guard 拦截三层分离
- [ ] 至少 2 个 human-in-the-loop 节点
- [ ] simulation 展示"用户会失去什么 / 得到什么"
- [ ] 撤销机制覆盖：手动 / 到期 / 异常自动暂停
- [ ] 审计日志字段完整
- [ ] 能展示 4 种场景对比：正常 / 超限 / 异常地址 / 撤销后
