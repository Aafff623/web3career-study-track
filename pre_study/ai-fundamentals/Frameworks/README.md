# Frameworks ｜ 开发框架

Frameworks 是帮助你快速搭建 AI 应用的工具库。它们封装了模型调用、工具编排、记忆管理、RAG 管道等常见模式，让你不用从零造轮子。但框架不是银弹——选错框架会增加复杂度，用错框架会让简单问题变难。

## 为什么要学这个

自己从零写一个 AI 应用，你会发现大量时间花在重复造轮子上：模型调用格式、工具注册、上下文管理、错误处理、日志追踪。框架的价值在于把这些通用模式封装好，让你专注于业务逻辑。

但框架也有代价：它引入了抽象层，你需要理解框架的运行方式才能调试问题；框架的版本更新可能带来 breaking change；有些框架过度封装，反而让你更难理解和控制底层行为。

> *Frameworks 的核心价值不是"少写代码"，而是"管理工程复杂度"。选框架时要问：它解决的问题是不是我真正遇到的？它的抽象是不是让我更容易理解系统行为？*

## 第一性原理

**框架是工具，不是架构。先想清楚系统要做什么，再选框架。**

很多 AI 应用的问题不是"用了什么框架"，而是"没想清楚系统要做什么"就直接选了一个框架开始堆代码。框架应该服务于架构，而不是反过来。

- **先画数据流，再选框架**：你的系统需要哪些输入、哪些处理步骤、哪些输出？数据怎么在各步骤之间流动？
- **先定义接口，再看框架支持**：模型调用、工具调用、外部 API 调用的接口是什么？框架能否自然支持这些接口？
- **先跑最小版本，再决定是否需要框架**：很多时候，直接调用 API + 简单的编排逻辑就够了，框架反而增加了不必要的复杂度。

> *先想清楚系统要做什么，再选工具。框架是为架构服务的，不是反过来。很多时候直接调 API + 简单逻辑就够了，不需要框架。*

## 知识节点


### LangChain

LangChain 是最流行的 LLM 应用开发框架之一。它提供了模型调用、Prompt 模板、工具注册、链式编排、RAG 管道等通用模式。

LangChain 的优势是生态丰富、文档完善、社区活跃。劣势是抽象层较深，调试时需要理解框架内部的运行机制。

> *LangChain 是"全功能型"框架——它想帮你处理 LLM 应用的所有环节。适合快速原型，但生产环境要注意：它的抽象可能让你更难理解底层发生了什么。*


### LangGraph

LangGraph 是 LangChain 团队推出的 Agent 编排框架。它基于有向图的概念，把 Agent 的执行流程建模为状态机——节点是处理步骤，边是状态转换条件。

LangGraph 的优势是让复杂的 Agent 流程变得可视化和可调试。每个步骤的输入输出都是明确的状态，方便追踪和回放。

> *LangGraph 的核心是把 Agent 流程变成"可追踪的状态图"。在 AI×Web3 里，交易分析、风险评估这种多步流程用状态机来管理，比纯 ReAct 模式更容易调试和审计。*


### Vercel AI SDK

Vercel AI SDK 是前端友好的 LLM 应用工具库。它专注于流式输出、React 集成和 TypeScript 类型安全，让前端开发者更容易构建 AI 驱动的用户界面。

它的设计理念是"AI 是 UI 的一部分"——模型调用、流式渲染、工具调用都直接集成到前端组件里，不需要额外的后端服务。

> *Vercel AI SDK 的定位是"让前端开发者更容易做 AI 应用"。如果你的 AI 功能主要在前端展示（流式文本、工具调用结果、实时交互），它比 LangChain 更自然。*


### Learning Agent 框架

Learning Agent 框架关注的是 Agent 的自我改进能力。它让 Agent 能从执行结果中学习、调整策略、优化工具使用方式。

这类框架通常包含反馈循环：Agent 执行任务 → 评估结果 → 调整策略 → 再次执行。在生产环境中，它需要配合评估指标和日志系统才能有效工作。

> *Learning Agent 的核心是"让 Agent 能从结果中学习"。但在生产环境里，盲目让 Agent 自我调整是危险的——学习过程需要评估指标和人工监督来保证方向正确。*

## 在 AI x Web3 中的位置

Frameworks 在 AI×Web3 系统中通常服务于编排层和执行层。选择哪个框架取决于你的应用场景：

| 场景 | 推荐框架 | 原因 |
|------|----------|------|
| 快速原型验证 | LangChain | 生态丰富，快速搭建 |
| 复杂 Agent 流程 | LangGraph | 状态机模型，可追踪 |
| 前端 AI 功能 | Vercel AI SDK | React 集成，流式输出 |
| 自适应系统 | Learning Agent | 反馈循环，自我优化 |

> *选框架不是"选最流行的"，而是"选最适合你场景的"。在 AI×Web3 里，链上交互的复杂性往往需要自定义编排逻辑——框架应该能被拆开用，而不是只能整个用。*

## 最小实践

用不同框架实现同一个功能：读取一个交易哈希，返回结构化的交易分析。

比较点：
1. 代码量和复杂度
2. 工具注册和调用的便利性
3. 流式输出支持
4. 调试和日志能力
5. 与链上数据源的集成难度

> *这个练习的目的不是"哪个框架更好"，而是理解每个框架的设计取舍。同一个任务用不同框架实现，你会直观感受到它们在抽象层级、灵活性和开发体验上的差异。*
