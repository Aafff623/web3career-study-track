Agent 是能自主使用工具、规划步骤、执行任务的 AI 系统。它不只是"回答问题"，而是"完成任务"——理解目标、制定计划、调用工具、处理结果、根据反馈调整。

## 为什么要学这个

很多 AI 应用的链路是：用户提问 → 模型回答 → 结束。但在真实工作流里，用户要的往往不是一段文字，而是一个动作：查余额、发起交易、更新数据、执行策略。

Agent 的价值在于把"模型生成文本"变成"模型驱动行动"。它让模型不只是知识的出口，而是任务的执行者。

> *Agent 的核心是"模型不只是回答问题，而是完成任务"。在 AI×Web3 里，这意味着模型可以读取链上数据、分析风险、准备交易方案，而不是只解释概念。*

## 第一性原理

**Agent 的自主性来自工具调用能力，但自主性越高，安全风险越大。**

Agent 能调用的工具越多、能执行的动作越敏感，系统需要的安全边界就越严格。模型可以决定"什么时候调用工具"和"调用哪个工具"，但"工具实际能做什么"必须由代码层控制。

- **工具定义是权限边界**：模型只能调用你暴露的工具，工具的权限范围就是 Agent 的行动边界。
- **工具调用需要校验**：模型生成的工具参数可能有误、有偏差、有安全风险，调用前必须做参数校验。
- **高风险动作需要人在回路**：签名、转账、合约调用等不可逆操作，Agent 可以准备方案，但执行必须经过人工确认。

> *Agent 的安全模型：模型负责决策，代码负责执行。模型决定"做什么"，代码决定"能不能做"和"怎么做"。在 AI×Web3 里，签名和转账是不可逆的——Agent 只能建议，不能直接执行。*

## 知识节点


### Tool Use（工具调用）

Tool Use 是 Agent 的核心能力。模型根据任务需要，决定调用哪个工具、传什么参数、怎么处理返回结果。

工具可以是任何外部接口：API、数据库查询、链上数据读取、模拟执行、签名接口。模型不直接执行这些操作——它生成调用意图，系统负责实际执行和结果回收。

> *Tool Use 让模型从"文本生成器"变成"任务执行者"。但工具调用是模型的"手"——它只能抓你给它的东西，抓的过程也需要校验。*


### Planning（规划）

Planning 是 Agent 拆解复杂任务为可执行步骤的能力。面对一个多步任务（比如"分析这笔交易的风险并准备建议"），Agent 需要决定：先做什么、后做什么、哪些可以并行、遇到意外怎么调整。

规划能力让 Agent 能处理超出单次推理范围的复杂任务。但规划本身也是模型的推测——它可能规划出不合理或不可行的步骤，所以规划结果需要校验。

> *Planning 让 Agent 能处理多步任务，但规划质量取决于模型对任务和工具的理解。在 AI×Web3 里，一个完整的交易分析可能需要读取链上数据、检索文档、模拟执行、评估风险——每一步都需要合理的规划。*


### ReAct 模式

ReAct（Reasoning + Acting）是 Agent 最基础的运行模式：模型先推理（思考当前情况和下一步行动），再行动（调用工具），再观察（看工具返回结果），循环往复直到任务完成。

ReAct 的优势是每一步都有明确的推理和行动记录，方便调试和审计。劣势是串行执行——每一步都依赖上一步的结果，复杂任务可能很慢。

> *ReAct 是 Agent 的"思考-行动-观察"循环。在 AI×Web3 里，这个模式很适合交易分析：先读数据、再推理风险、再查文档、再评估、最后给建议。每一步都有迹可循。*


### Orchestrator-Worker 模式

Orchestrator-Worker 是更复杂的 Agent 架构：一个编排器（Orchestrator）负责任务拆解和分配，多个工作者（Worker）各自处理子任务，最后由编排器汇总结果。

这种模式适合需要并行处理或多角度分析的任务。比如同时分析一笔交易的安全风险、经济影响和合规性，三个 Worker 各自分析，编排器汇总成完整报告。

> *Orchestrator-Worker 让 Agent 能并行处理复杂任务。但架构越复杂，调试和审计越难——在 AI×Web3 里，多 Agent 协作需要清晰的日志和状态追踪。*

## 在 AI x Web3 中的位置

Agent 在 AI×Web3 系统中通常处于编排层和执行层之间。它接收用户意图，通过工具调用获取链上数据和外部信息，经过推理后生成候选动作或建议。

一个典型的 Agent 链路：

1. 用户表达意图（"帮我看看这笔交易"）
2. Agent 规划步骤（读交易数据 → 查合约 ABI → 检索安全文档 → 模拟执行 → 评估风险）
3. 每一步调用相应工具，拿到结果
4. Agent 基于所有结果生成分析报告
5. 高风险动作标记为需要人工确认

> *这条链路的核心判断：Agent 可以自主规划和执行多步任务，但每一步的工具调用都需要代码层校验，高风险动作必须经过人工确认。Agent 是"聪明的助手"，不是"有权限的执行者"。*

## 最小实践

做一个"DAO 提案研究"Agent。

功能：
1. 接收一个提案编号或链接
2. 自动检索提案内容、相关讨论、历史投票数据
3. 分析提案的潜在影响（经济、治理、安全）
4. 输出结构化报告：提案摘要、影响分析、风险点、不确定性、建议的进一步检查

> *这个练习的设计思路：让 Agent 自主规划多步任务——检索、分析、评估、组织。重点不是最终报告有多完整，而是 Agent 在每一步是否能合理选择工具、处理结果、标记不确定性。*
