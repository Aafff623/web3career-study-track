# Practice: 开放赛道项目规格页

> 模块：前沿探索 · Open-Track

## 目标

为一个开放赛道项目写一页完整规格，覆盖用户 → 痛点 → AI/Web3 职责 → 最小闭环 → 失败路径。

## 项目：链上数据分析 Agent（On-chain Data Analyst）

### 1. 用户画像

| 属性 | 描述 |
|------|------|
| 用户 | DeFi 投资者 / 协议研究者 / 安全分析师 |
| 场景 | 分析某个地址的 DeFi 行为、识别风险、追踪资金流向 |
| 现有方式 | 手动查 Etherscan + Dune + 协议文档，耗时 2-4 小时 |
| 痛点 | 数据分散、跨协议难关联、异常难发现、无法快速生成报告 |

### 2. 工作流痛点

```
当前流程（手动）：
1. 打开 Etherscan 查地址交易 → 复制关键交易
2. 打开 Dune 查协议交互 → 截图
3. 打开协议文档查函数含义 → 对照 ABI
4. 手动判断是否有异常（大额转出/异常授权/高频操作）
5. 写报告 → 1-2 天

痛点：
- 数据分散在 3+ 个平台
- 跨协议关联需要人工
- 异常检测靠经验
- 报告生成慢
```

### 3. AI 与 Web3 职责分工

| 步骤 | 职责 | 技术 |
|------|------|------|
| 查询链上数据 | Web3 | RPC + The Graph + Dune API |
| 理解交易含义 | AI | Transaction Interpreter |
| 识别异常模式 | AI | Pattern Detection |
| 关联跨协议行为 | AI + Web3 | 地址聚类 + 协议识别 |
- 生成结构化报告 | AI | Report Generator |
| 验证数据来源 | Web3 | 链上 hash + 区块浏览器链接 |
| 保存报告 | Web3 | IPFS + 链上 hash |

### 4. 最小输入 / 处理 / 输出

```json
{
  "input": {
    "address": "0xABC...",
    "chain": "ethereum",
    "time_range": "30d",
    "focus": ["defi", "token_transfers"]
  },
  "processing": [
    "查询交易历史",
    "解析合约调用",
    "识别协议交互",
    "检测异常模式",
    "生成风险评分"
  ],
  "output": {
    "summary": "该地址在 30 天内交互了 5 个 DeFi 协议...",
    "risk_score": 65,
    "anomalies": ["大额 USDC 转出到新地址", "高频 approve 操作"],
    "protocol_breakdown": {...},
    "source_links": ["etherscan.io/tx/0xabc..."],
    "report_ipfs": "Qm..."
  }
}
```

### 5. 权限、隐私和失败路径

| 维度 | 设计 |
|------|------|
| 权限 | 只读链上数据，不签名不转账 |
| 隐私 | 只查询公开数据，不访问私钥 |
| 失败路径 | RPC 失败→重试；数据不完整→标注缺失；异常检测失败→标记为未验证 |

### 6. Demo 验证

- [ ] 输入一个地址，2 分钟内生成结构化报告
- [ ] 报告包含至少 5 个来源链接
- [ ] 异常检测能识别大额转出和高频授权
- [ ] 风险评分有明确依据
- [ ] 报告可导出为 JSON + Markdown

- [ ] 最小输入/处理/输出定义完整
- [ ] 权限/隐私/失败路径覆盖
- [ ] Demo 验证标准可执行
