# 实践：钱包交互地图

## 目标

完整走一遍钱包交互流程，理解每一步的权限边界和风险等级，区分读取操作与状态变更操作。

## 流程

1. **连接钱包**
   - 用测试钱包连接一个测试网 dApp（如 Uniswap Testnet）
   - 观察弹窗：应用请求了什么？（地址、网络）
   - 记录：这一步只是读取，没有资产风险

2. **切换网络**
   - 在 dApp 中切换网络（如 Sepolia → Mainnet）
   - 观察：地址不变，但资产和状态可能完全不同

3. **签名消息**
   - 触发一次消息签名（如登录、授权）
   - 记录签名请求内容：目的、域名、数据
   - 对比：签名 ≠ 发交易，不转移资产

4. **发送交易**
   - 发起一笔测试网转账或 swap
   - 观察钱包弹窗的完整信息：链、合约地址、gas、资产变化
   - 记录交易哈希，在 explorer 中查看状态

5. **查看 Explorer**
   - 用区块浏览器查看刚才的交易
   - 逐项检查：Status、From/To、Method、Value、Token Transfers、Logs、Gas Used

6. **权限分级总结**

| 动作 | 权限等级 | 会改变链上状态？ | 风险等级 |
|------|---------|:---:|:---:|
| 连接钱包 | 读取 | ❌ | 低 |
| 切换网络 | 读取 | ❌ | 低 |
| 签名消息 | 授权 | ❌（通常） | 中 |
| 发送交易 | 执行 | ✅ | 高 |

7. **Agent 辅助思考**
   - 哪些步骤 AI 可以代劳？（解释交易、准备参数、检查风险）
   - 哪些步骤必须人工确认？（签名、发送交易）
   - 如果 Agent 要自动执行，需要什么约束？（金额上限、时间窗口、白名单合约）

## 验收标准

- [ ] 能说清连接/签名/交易三类动作的区别
- [ ] 能在 explorer 中读懂一笔交易的基本信息
- [ ] 能说出哪些操作会改变链上状态
- [ ] 能描述 Agent 辅助钱包交互时的权限边界
