# 实践：事件索引设计

> 模块：Web3 基础 · Indexing · 状态：✅

## 目标

选择一个简单合约，设计 event 与查询表，验证索引层如何把链上事实转换为可用数据，并思考 Agent 消费索引数据时的额外需求。


## 流程

1. 选择一个简单合约作为练习对象（投票合约、计数器、NFT mint 等均可），阅读其源码，列出所有 event 定义。
2. 对每个 event，分析其参数：哪些是 indexed，哪些是非 indexed，每个参数对应什么业务含义。
3. 设计一张查询表（可用 SQL schema 或 Markdown 表格），字段需覆盖 event 参数 + 交易级元数据（block number、tx hash、timestamp、from address）。
4. 标出每个字段的数据来源——来自哪个 event 参数、哪笔交易字段、还是需要额外调用 RPC 补充。
5. 写出 reorg 处理策略：当链发生 reorg 时，如何标记或清理受影响的索引记录。
6. 写出去重策略：同一笔交易可能产生多个同类型 event，如何避免重复入库。
7. 写出合约升级兼容方案：如果合约升级后 event 结构变化，索引层如何平滑迁移。
8. 最后追问：如果这张表要给 AI Agent 使用，需要额外附带哪些字段？（建议思考：数据来源可信度、最后更新时间、是否有 reorg 风险、是否经过解码校验）


## 验收标准

- [ ] 列出了目标合约的所有 event 及其参数分析
- [ ] 设计了至少一张查询表，包含 event 参数 + 交易元数据
- [ ] 每个字段标注了数据来源（event 参数 / tx 字段 / RPC 补充）
- [ ] 写出了 reorg 处理策略
- [ ] 写出去重策略
- [ ] 写出合约升级兼容方案
- [ ] 补充了 Agent 消费场景下需要的额外字段设计
