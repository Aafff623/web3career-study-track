# 实践：签名观察练习

## 目标

通过实际操作测试钱包，观察密码学元素在链上交互中的表现，区分哪些信息可公开、哪些绝对不能公开。

## 流程

1. **创建测试钱包**（不放真实资产）
   - 用 MetaMask 或其他钱包创建一个新的测试钱包
   - 记录下地址（可公开）

2. **发起一次签名**
   - 在测试环境连接 dApp，触发一次消息签名
   - 观察钱包弹窗中的签名请求内容

3. **发起一次转账**
   - 向测试地址发起一笔小额转账
   - 在区块浏览器（如 Sepolia Etherscan）查看交易详情

4. **记录观察**

| 信息 | 能否公开 | 原因 |
|------|---------|------|
| 地址 | ✅ | 公钥派生的标识，公开无风险 |
| 交易哈希 | ✅ | 数据指纹，不含密钥信息 |
| 签名内容（消息） | ⚠️ 看情况 | 取决于消息是否包含敏感信息 |
| 私钥 | ❌ | 控制权本身，泄漏 = 资产丢失 |
| 助记词 | ❌ | 私钥的备份形式，同上 |
| 签名（签名值） | ⚠️ 谨慎 | 可被重放，需检查链 ID 和 nonce |

5. **对比分析**
   - "签名消息"（personal_sign / EIP-712）：只签名，不转移资产
   - "发送交易"（sendTransaction）：签名 + 链上执行，资产会移动

## 验收标准

- [ ] 能在区块浏览器中找到自己的交易哈希
- [ ] 能区分"签名消息"和"发送交易"的区别
- [ ] 能说出至少 3 种绝不能公开的信息
- [ ] 理解为什么地址可以公开但私钥不行
