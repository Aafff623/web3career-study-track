### 2. Neo-Cypherpunk 直播笔记

**提交要求**：实时参与截图 + 1 条关键信息 / 问题 / 下一步行动

- 截图：`./assets/neo-cypherpunk-0527.png`（待补充）
- 关键收获：
  > **隐私的本质是"选择性披露"而非"隐藏"**——cypherpunk 传统的核心不是让一切不可见，而是让个体拥有决定"对谁在什么条件下披露什么"的能力。Session Key 的设计哲学与此高度同构：用户不是把钱包交给 Agent，而是设定一道"有条件的透明窗口"。这个叙事比"安全"更有张力，可以作为 Hackathon Proposal 的切入点。

**3 条有效笔记**（回放任务备选 / 实时任务补充）：

1. **隐私的文化层 vs 技术层**：技术层是加密、零知识证明、混币；文化层是"个人主权"的社会契约。cypherpunk 宣言里"隐私权是选择性向世界披露自己的权利"这句话直接映射到 Session Key 的权限设计——用户选择让 Agent 在什么时间窗口内、什么金额上限下、对什么合约有操作权。

2. **"Why Privacy Matters for Builders" 的核心论点**：Builder 容易把隐私当成合规成本或高级功能，但嘉宾强调的视角是——**隐私是产品信任的基底**。对 Smart Account 来说，用户敢不敢把权限签发给 Agent，取决于他是否相信这个权限是"可验证地受限"。Session Key 的链上策略表达式 + 用户随时可撤销，本质上是在构建这种信任。

3. **Neo-cypherpunk 与 AI Agent 的交叉点**：传统 cypherpunk 关注个人对抗国家/企业 surveillance；Neo-cypherpunk 的延伸是——当 Agent 成为用户的数字延伸时，Agent 的行为数据谁来控制？Smart Account 的 Audit Trail 设计如果做在用户端（用户自己持有完整的 Agent 操作日志，链上只存 hash 证明），既满足可审计性又保留隐私。这是一个可以在 Hackathon 里作为差异化亮点的设计。

## 收获 / 卡点

- **Co-learning 的意外收获：方向被"向下兼容"了**——原以为 Smart Account + Session Key 是一个比较安全的保守选择，但讨论中发现这个方向的差异化空间比想象中大。特别是"链上 Audit Trail + 用户本地完整日志"的双层设计，既满足 05-26 Cobo 分享中提到的机构级审计需求，又回应了今天 Neo-Cypherpunk 的隐私主权叙事。一个技术方案能同时接住两条线的输入，说明方向选得对。

- **Neo-Cypherpunk 给了一个比"安全"更好的叙事框架**——之前写 DIRECTION.md 时，核心卖点是"可限制、可审计、可撤销"，属于功能描述。今天的收获是，可以从隐私主权角度重新包装："Agent 不应该拥有你的钱包，它只应该拥有你明确授权的能力——并且这个授权是透明的、可验证的、随时可收回的。"这个表述对评委和用户的感染力都更强。

- **卡点在技术预研的启动阻力**——概念层已经比较清晰了（Session Key 两维策略 + Audit Trail 双层设计），但还没开始动手看 ZeroDev SDK 的实际接口。担心文档读起来比想象中复杂，或者 SDK 的 Session Key 权限模型不支持自定义策略表达式。明天必须开始，不能再拖。
