## 今天做了什么

晚上连参加了两场活动：Women Builders 和 Week 2 例会。

Women Builders 那场干货密度其实挺高的，不是泛泛而谈的"女性赋能"，而是直接聊了两个可以落地的技术交叉点：

1. **去中心化推理验证** —— 用 Web3 的共识/质押机制去校验 AI 输出，类似 opML 或 zkML 的轻量版。之前只在推特上刷到过概念，今天第一次听到有人讲清楚"为什么链上验证推理比链上跑推理更现实"。

2. **AI agent 的链上资源调度** —— agent 调用算力/API/数据的时候，用智能合约做支付和权限管理，而不是背后挂一个中心化后端。这个和我之前想的"AI 生成内容版权上链"完全不是一个量级，但反而更务实。

例会部分主要是优秀笔记展示和答疑，最大的收获是看到别人的问题地图长什么样 —— 发现自己的结构太散了，假设之间没有递进关系。

## 收获 / 卡点

**最大的转折**：Week 2 的问题地图原本主方向是"AI 生成内容版权上链"，今天听完后果断觉得太重了。版权涉及法律边界、内容溯源、争议仲裁，2 周 Hackathon 根本跑不完。反而"轻量级 agent 调用审计 + 小额激励"这个 slice 更小、更可验证、也更有链上原生感。

**现场问的一个问题**（简化了）：有没有人试过用链上简单 mapping + 链下向量数据库，做一个极简的 agent 调用记录？不是为了防作弊，只是为了可审计。

得到的答案是：完全可以，而且不需要高性能 L1，L2 或 DA 层就够。这个回答直接降低了我周末 demo 的技术门槛。

**卡点**：LangChain 还在学，对 agent 编排的逻辑还不是特别熟，周末搭 demo 的时候可能会卡在怎么把链下调用和链上记录串起来。
