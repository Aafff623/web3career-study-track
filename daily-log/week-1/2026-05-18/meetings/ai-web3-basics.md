# AI 时代，Web3 开发者需要具备的基础知识与架构能力

> 类型：线上直播 · 日期：2026-05-18 · Week 1

## 核心笔记

### 1. AI 与人的关系：协作而非替代

AI 协助制定方案，产出后人负责 review 验收。不是"AI 替代人"，而是"人驾驭 AI"。

### 2. Web3 是什么

Web2 占比很多：前端交互 UI、后端业务逻辑系统。Web3 的核心是**资金交互安全**，需要人为拥有业务理解，解析系统行为，打造优化 Agent 链路。

### 3. Web2 & Web3 典型支付流对比

| | Web2 | Web3 |
|--|------|------|
| 信任基础 | 权威机构背书 | 算法共识 + 不可篡改数据 + 透明代码 |
| 信息流 | 回调支付信息 | Pull chain 上面的信息进行监听，fallback 到收款方 |
| 核心差异 | 信任"人/机构" | 信任"算法" |

### 4. 私钥签名机制

- Web3 通过私钥签名校验请求
- 钱包让用户控制财产
- 算法控制私钥对应的签名方式：**交易签名**、**消息签名**
- 签名证明意图和身份
- 私钥不变，消息不同 → 签名不同
- 流程：A 给 B 一个消息 → B 用私钥签名 → A 识别 → 去中心化算法背书

### 5. 私钥安全：不可逆

- Web3 认 private key 而不认人
- 泄漏/丢失 = 控制权丢失，不可逆
- 处置资产需要私钥签名
- 需要提高钱包安全性

### 6. 钱包分类

| 类型 | 特点 |
|------|------|
| 多签 | 秘钥权限多人共享，MPC 算法（数学美感） |
| 硬件 | 二维码/扫码，离线存储 |
| 隐私 | 隐藏交易细节 |
| 合约钱包 | 天然支持多签，适合公司/协作场景多拆 |
| 全托管 | 跟交易所进行 Web2 服务，私钥存别人服务器，有跑路风险 |
| 混合 | 分片 + 多人协同，签名需要多个分片方认同 |

### 7. 安全要点

- **签名可视化**：防止被交易实际金额的钓鱼欺骗
- **权限滥用**：需要严格控制签名范围

### 8. Web3 交易生命周期

```
交易信息 → 私钥签名 → Web3 blockchain 广播交易
```

### 9. 交易参数

| 参数 | 作用 |
|------|------|
| Gas | count = 消耗资源，price = 消耗金额，交易模型 |
| Nonce | 保证幂等，顺序递增 |
| Data | 指令集 |

### 10. 监听逻辑

- 交易确认
- Event 监听
- 存在不确定性

### 11. 交易模拟

**必须在签名之前进行模拟**，签名之后模拟没有意义。

### 12. Server 侧钱包安全

- 资金拆分多签（减少单签风险）
- 大金额需要审核
- 交易模拟（此时还未开始私钥签名）

### 13. Web3 安全要求极高

- Web2 可以冻结、回滚
- Web3 出错 = 直接资产损失，不可逆

### 14. AI 引发效率革命

- AI 提供"三头六臂"，但系统复杂度和体量没变
- 方案、思考、决策、架构、安全仍然不可忽视
- 之后的范式：**Harness（驾驭）AI**

### 15. AI 架构师能力

- 架构设计
- 独特理解
- 风险洞察
- Debug 能力
- 基础扎实
